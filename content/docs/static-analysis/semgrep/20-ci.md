# 継続的インテグレーション

## CI/CD への組み込み

この章では、継続的インテグレーション (CI) と継続的デプロイ (CD) のパイプラインの一部として、
Semgrep を GitHub リポジトリに組み込む手順を説明します。

### Semgrep と GitHub の組み込みの推奨方法

GitHub Actions に Semgrep を組み込むには、次の方法をおすすめします。

1. 幅広い Semgrep ルール (例: `p/default`) で、main ブランチに対する Semgrep のフルスキャンをスケジュールします。
2. プルリクエストには、確度が高く真陽性になりやすいように調整したルールセットで、差分を認識するスキャンを実施します。
3. Semgrep の運用が成熟したら、未解決の Semgrep の検出結果がある場合に PR のパイプラインをブロックするよう設定します。
   - 参照: [Require status checks before merging / GitHub Docs](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/defining-the-mergeability-of-pull-requests/about-protected-branches#require-status-checks-before-merging)

### Semgrep CI の設定オプションを理解する

[Configuration reference](https://semgrep.dev/docs/semgrep-ci/configuration-reference/)を見て、使える環境変数とその既定値に慣れておきましょう。
押さえておきたい要点は次のとおりです。

- Semgrep は既定で新しいバージョンを確認します。これは `SEMGREP_ENABLE_VERSION_CHECK` 変数で制御されます。
- 既定では、Semgrep が実行する個々の Git コマンドに、5 分のタイムアウトが設定されます (`SEMGREP_GIT_COMMAND_TIMEOUT`)。
- Semgrep は、各ファイルを 30 秒のタイムアウト (`SEMGREP_TIMEOUT`) でスキャンしようとし、最大 3 回まで再試行します (`--timeout-threshold`)。
- 環境変数 `SEMGREP_RULES` は、Semgrep が使うルールを定義します。複数のルールのソースを、
  スペースで区切って指定できます。
- 既定では、検出結果があると CI は失敗しますが、内部エラーが起きても成功します。詳しくは、
[Passing or failing the CI job](https://semgrep.dev/docs/semgrep-ci/running-semgrep-ci-without-semgrep-app/#passing-or-failing-the-ci-job) を参照してください。
- 検出結果を [GitHub Advanced Security Dashboard](https://semgrep.dev/docs/semgrep-ci/sample-ci-configs#:~:text=Alternate%20job%20that%20uploads%20findings%20to%20GitHub%20Advanced%20Security%20Dashboard) にアップロードするジョブの例を参照してください。

#### CI/CD にカスタムの Semgrep ルールを追加する

`SEMGREP_RULES` に渡す標準のルールセット (`p/default` や `p/javascript` など) に加えて、
独自のカスタムルールを使いたい場合は、次の手順に従います。

1. カスタムの Semgrep ルールのディレクトリが、スキャン対象のコードと**同じ**リポジトリにある場合は、
       `SEMGREP_RULES` 変数にそのディレクトリのパスを渡すだけです。
      (例: `SEMGREP RULES: p/default custom-semgrep-rules-dir/`)

2. カスタムの Semgrep ルールが**別のプライベートリポジトリにある**場合は、次のようにします。

    a. [Semgrep ルールのリポジトリ用のアクセストークンを生成します](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
    必要最小限のスコープを選ぶことを忘れないでください (例: リポジトリの内容への読み取り専用のアクセスだけを持つ、
    そのリポジトリ用のきめ細かいトークン)。

    b. [生成したアクセストークンを](https://docs.github.com/en/actions/security-guides/using-secrets-in-github-actions)、
    ワークフローを実行するリポジトリにシークレットとして追加します。

    c. メインのソースコードのチェックアウトのあとに、`actions/checkout` のステップをジョブに追加し、次を指定します。
      - `repository` の名前
      - リポジトリの取得に使う個人用アクセス `token` (PAT)
      - リポジトリを置く相対 `path`

    d. カスタムの Semgrep ルールがあるディレクトリのパスを、環境変数 `SEMGREP_RULES` に渡します。

    {{< hint info >}}
カスタムルールのリポジトリが公開されている場合は、PAT を作る手順を省き、チェックアウトのステップで
`token` を渡さないようにします。
    {{< /hint >}}

    例:

    ```yaml
    # Set up an environment variable containing the name of the private repository with custom Semgrep rules
    env:
      SEMGREP_PRIVATE_RULES_REPO: semgrep-private-rules
    steps:
        # Main checkout of the repository source code
      - name: Checkout main repository
        uses: actions/checkout@v4
        # Checkout of the repository with custom Semgrep rules
      - name: Checkout private custom Semgrep rules
        uses: actions/checkout@v4
        with:
          repository: ${{ github.repository_owner }}/${{ env.SEMGREP_PRIVATE_RULES_REPO }} # organization-name/semgrep-private-rules
          token: ${{ secrets.SEMGREP_RULES_TOKEN }} # Configured PAT
          path: ${{ env.SEMGREP_PRIVATE_RULES_REPO }} # Relative path to place the repository
        # ...
      - run: semgrep ci
        env:
          # Pass the directory with the checked-out Semgrep rules repository
          SEMGREP_RULES: ${{ env.SEMGREP_PRIVATE_RULES_REPO }}
    ```

### GitHub への組み込み手順

Semgrep を GitHub リポジトリに組み込むには、次の手順に従います。

1. スキャンしたいリポジトリの `.github/workflows` ディレクトリに、`semgrep.yml` ファイルを作ります。
2. 下のコードスニペットを `semgrep.yml` ファイルにコピーします。このワークフローは、2 つのジョブでできています。
     - 1 つ目のジョブ:
       - スケジュールに基づいて実行されます (月に 1 回)。
       - プルリクエストがマージされたときに実行されます。
       - main/master ブランチに直接プッシュされたときに実行されます。
       - 幅広い `p/default` の Semgrep ルールを使います。
     - 2 つ目のジョブ:
       - プルリクエスト専用に実行されます。
       - セキュリティ関連の複数のルールを使います。

```yaml {linenos=inline}
# Define the name of this GitHub Actions workflow.
name: Semgrep
on:
  # Run the workflow on pull_request events for diff-aware scanning.
  pull_request: {}
  # Run the workflow on push events to mainline branches to report all findings.
  push:
    branches: ["master", "main"]
  # Schedule the workflow to run periodically using cron syntax.
  schedule:
    - cron: '0 0 1 * *' # Schedule Semgrep to run once per month (at 00:00 on day-of-month 1).
# Define the jobs that run as part of this workflow.
jobs:
  # Define the first job for scheduled scanning and mainline branch scanning.
  semgrep-schedule:
    # Define the conditions for running this job. Run on schedule, push to master/main, or merged PR.
    # Skip any PR created by Dependabot to avoid permission issues.
    if: ((github.event_name == 'schedule' || github.event_name == 'push' || github.event.pull_request.merged == true)
        && github.actor != 'dependabot[bot]')
    # Name this GitHub Actions job.
    name: Semgrep default scan
     # Define the environment in which the job runs.
    runs-on: ubuntu-latest
    container:
      # Use a Docker image with Semgrep pre-installed.
      image: returntocorp/semgrep
    # Set up an env variable - the name of the (private) repository with custom Semgrep rules
    # env:
      # SEMGREP_PRIVATE_RULES_REPO: semgrep-private-rules
    steps:
      # Use the GitHub Actions Checkout step to fetch the project source code.
      - name: Checkout main repository
        uses: actions/checkout@v4
      # In case you have a (private) repository with custom Semgrep rules:
      # - name: Checkout custom Semgrep rules
      #   uses: actions/checkout@v4
      #   with:
      #     repository: ${{ github.repository_owner }}/${{ env.SEMGREP_PRIVATE_RULES_REPO }}
      #     token: ${{ secrets.SEMGREP_RULES_TOKEN }} # If the repository is private
      #     path: ${{ env.SEMGREP_PRIVATE_RULES_REPO }}
       # Execute the "semgrep ci" command within the Semgrep Docker container.
      - run: semgrep ci
        env:
          # Set the SEMGREP_RULES environment variable to specify which rules Semgrep should use.
          # Use common security-related rulesets for this job (starting with `p/`)
          # or use a directory with your custom rules from the current repository (such as `semgrep-rules/`).
          SEMGREP_RULES: >
            p/default
          # If you have a directory in the current repo with your custom rules:
          # semgrep-rules/
          # Pass the directory with the checked-out Semgrep rules repository
          #  ${{ env.SEMGREP_PRIVATE_RULES_REPO }}
  # Define the second job for scanning pull requests.
  semgrep-pr:
    # Define the conditions for running this job. Run only within Pull Requests, excluding Dependabot PRs.
    if: (github.event_name == 'pull_request' && github.actor != 'dependabot[bot]')
    # Name this GitHub Actions job.
    name: Semgrep PR scan 
    # Define the environment in which the job runs.
    runs-on: ubuntu-latest
    container:
      # Use the GitHub Actions Checkout step to fetch the project source code.
      image: returntocorp/semgrep
    steps:
      # Fetch project source with GitHub Actions Checkout.
      - uses: actions/checkout@v4
      # Execute the "semgrep ci" command within the Semgrep Docker container.
      - run: semgrep ci
        env:
          # Set the SEMGREP_RULES environment variable to specify which rules Semgrep should use.
          # Use common security-related rulesets for this job (starting with `p/`)
          # or use a directory with your custom rules from the current repository (such as `semgrep-rules/`).
          SEMGREP_RULES: > 
            p/cwe-top-25
            p/owasp-top-ten
            p/r2c-security-audit
            p/javascript
            p/trailofbits
          # If you have a directory in the current repo with your custom rules:
          # semgrep-rules/
```

この設定により、コードベースが定期的に潜在的な問題についてスキャンされ、
プルリクエストで追加された新しいコードも、セキュリティ上の脆弱性について十分にチェックされます。
