# 継続的インテグレーション

## CI/CD への組み込み

この章では、GitHub リポジトリで CodeQL によるコードスキャンを有効にする手順を説明します。

{{< hint info >}}
コードスキャンは、公開の GitHub リポジトリで使えます。GitHub Advanced Security のライセンスを持つ組織が所有する非公開リポジトリでも使えます。詳しくは、公式ドキュメントの
[GitHub Advanced Security](https://docs.github.com/en/get-started/learning-about-github/about-github-advanced-security)を参照してください。
{{< /hint >}}

### CodeQL によるコードスキャン

GitHub のコードスキャンは、CodeQL を使った静的解析のフレームワークです。リポジトリでコードスキャンを有効にすると、このフレームワークが検出した問題が自動で通知されます。GitHub リポジトリでコードスキャンを有効にするには、リポジトリの設定ページの「Code security and analysis」を開き、「GitHub Advanced Security」を有効にします。これで、CodeQL によるコードスキャンを設定できるようになります。

{{< figure src="/code-scanning-setup.png" alt="Code scanning dialog in the GitHub settings page" >}}

コードスキャンのダイアログでは、既定の設定か独自の設定のどちらかで、コードスキャンを設定できます。既定の設定は出発点として適しており、リポジトリで使われている言語に応じたクエリスイートの集まりを有効にします。

既定の設定は、コードスキャンを手軽に始める方法ですが、複雑なプロジェクトではうまく動かないことがあります。特に、C や C++ のようなコンパイル言語のコードを含むプロジェクトでは、自動設定がプロジェクトのビルドシステムを検出できないことがあります。

自動設定に失敗した場合や、コードスキャンで独自のクエリを使いたい場合は、詳細設定のオプションをお勧めします。これを選ぶと、リポジトリに新しいコードスキャンのワークフロー設定が追加されます。この設定を編集して、言語の追加、独自のビルドスクリプト、新しいクエリパックを加えられます。

```yaml
name: "CodeQL"

on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]
  schedule:
    - cron: '34 10 * * 6'

jobs:
  analyze:
    name: Analyze

    runs-on: ${{ (matrix.language == 'swift' && 'macos-latest') || 'ubuntu-latest' }}
    timeout-minutes: ${{ (matrix.language == 'swift' && 120) || 360 }}

    permissions:
      actions: read
      contents: read
      security-events: write

    strategy:
      fail-fast: false
      matrix:
        language: [ 'cpp' ]
        # If your project contains more than one language supported by CodeQL you simply
        # list all of the language identifiers here. The workflow will run once for each
        # included language.

    steps:
    - name: Checkout repository
      uses: actions/checkout@v3

    # Initializes the CodeQL tools for scanning.
    - name: Initialize CodeQL
      uses: github/codeql-action/init@v2
      with:
        languages: ${{ matrix.language }}
        # If you wish to specify custom queries, you can do so here or in a config file.
        # By default, queries listed here will override any specified in a config file.
        # Prefix the list here with "+" to use these queries and those in the config file.

        # queries: security-extended,security-and-quality

    # Autobuild attempts to build any compiled languages (C/C++, C#, Go, Java, or Swift).
    # If this step fails, then you should remove it and run the build manually (see below)
    - name: Autobuild
      uses: github/codeql-action/autobuild@v2

    #   If the Autobuild fails above, remove it and uncomment the following three lines,
    #   suitably modified to build the codebase.

    # - run: |
    #     echo "Run, Build Application using script"
    #     ./location_of_script_within_repo/buildscript.sh

    - name: Perform CodeQL Analysis
      uses: github/codeql-action/analyze@v2
      with:
        category: "/language:${{matrix.language}}"
```

コンパイル言語では、上で示したように、autobuild のジョブを独自のビルドコマンドやスクリプトに置き換えて、ワークフロー設定を更新する必要があるかもしれません。

### 独自のクエリによるコードスキャン {#code-scanning-with-custom-queries}

コードスキャンが使うクエリスイートやクエリパックを設定するには、詳細設定のオプションを選び、実行するクエリパックを手動で指定します。これは、ワークフロー設定の「Initialize CodeQL」の部分を編集して行います。`queries` で、クエリスイートや個別のクエリを指定でき、`packs` で、公開されているクエリパックを指定できます。

```yaml
- uses: github/codeql-action/init@v2
  with:
    queries: security-extended,security-and-quality
    packs: trailofbits/cpp-queries
```

この例では、GitHub の `security-extended` と `security-and-quality` のクエリスイートに加えて、`trailofbits/cpp-queries` のクエリパックを追加しています。

### リポジトリ内のクエリによるコードスキャン

現在のリポジトリにあるクエリを、コードスキャンに含めることもできます。たとえば、リポジトリに CodeQL のクエリ `codeql/UnhandledError.ql` があれば、次のように、ワークフロー設定の `queries` にそのクエリを加えることで、コードスキャンのワークフローの一部として実行できます。

```yaml
- uses: github/codeql-action/init@v2
  with:
    queries: ./codeql/UnhandledError.ql
    packs: trailofbits/cpp-queries
```

これで、コードスキャンの結果には、リポジトリ内の `UnhandledError.ql` クエリが見つけた問題と、`trailofbits/cpp-queries` クエリパックが見つけた問題の両方が含まれます。

{{< hint info >}}
クエリのパスの先頭に `.` があることに注意してください。これは、クエリ名をリポジトリからの相対パスとして区別するために必要です。
{{< /hint >}}

{{< hint info >}}
すべてのクエリは、クエリパックの一部でなければならないことを忘れないでください。現在のリポジトリにコミットしたクエリの場合は、対応するクエリパックのルートディレクトリに、対応する `qlpack.yml` ファイルをコミットしておく必要があります。

`qlpack.yml` ファイルについて詳しくは、
[新しいクエリパックの作成]({{< relref "10-advanced#creating-new-query-packs" >}}).
{{< /hint >}}

{{< hint info >}}
CI/CD の一部として実行したいリポジトリ内のクエリが 1、2 個より多い場合は、`codeql pack install` でクエリパックをローカルにインストールし、ワークフロー設定の `packs` にクエリパックの名前を直接指定するほうがよいでしょう。
{{< /hint >}}

### コードスキャン結果のトリアージ

コードスキャンの結果は、リポジトリの「Security」タブにあります。

リポジトリの設定ページの「Code Security and Analysis」で、コードスキャンの結果にもとづくブランチ保護ルールを設定することもできます。
