# ファジングの環境 {#fuzzing-environments}

ほかのソフトウェアと同様に、ファザーの選択は、オペレーティングシステム、アーキテクチャ、ソフトウェアのバージョン、ハードウェアなどの要因で決まります。このセクションでは、ファジングに使う環境の選択に影響する要因を見ていきます。

**ハードウェアの選択。** ファザーが複数のコアでの実行に対応しているなら、多くのコアを使えるハードウェアを選びます。キャンペーンを定期的に実行する予定があるなら、ベアメタルサーバーを[レンタル](https://www.hetzner.com/sb?country=us)するか購入する価値があるかもしれません。そうでなければ、専有コアを多く備えた VM を[レンタル](https://www.digitalocean.com/pricing/droplets#cpu-optimized)するほうがおそらく適切です。 

SUT の 1 秒あたりの実行回数を多く確保することは、ファジングの構成に加えられるどんな小手先の工夫よりも効果が大きいはずだ、という点に留意してください。実行速度は非常に重要です。

**環境の選択。** 理想的には、SUT のユーザーが使うのと同じ環境でファジングします。ただし、ファジングを簡単にするために、普段は Windows や macOS で動く SUT を Linux でファジングしても問題ない場合があります。たとえば、macOS ではプロセスのフォークが Linux より[遅く](https://github.com/AFLplusplus/AFLplusplus/blob/358cd1b062e58ce1d5c8efeef4789a5aca7ac5a9/GNUmakefile#L589)なります(ファザーによっては問題にならないこともあります)。

Linux を含む多くのオペレーティングシステムに共通する注意点として、SUT がカーネルとやり取りする(たとえば、システムコールを通じて)場合、使うコアの数に比例して 1 秒あたりの実行回数が増えるとは限りません。SUT がカーネルと頻繁にやり取りするなら、それぞれ別のカーネルを動かす複数の VM でファジングすることを検討してください。目安として、24 コアを超えてファジングする場合は、複数の VM を使うとよいでしょう。これが関係するのは、LibAFL のように、複数のコアで性能がよく伸びるファザーだけです。

例として、すべてのプラットフォームに対応するゲームエンジンを考えます。この場合、最も簡単な選択は Linux でのファジングです。全体として最もよく対応しているプラットフォームだからです。ただし、そうすると Windows だけに影響するバグを見逃すかもしれません。これは、自分で判断すべきトレードオフです。最も簡単な環境から始めて、そのあとで繰り返しほかのプラットフォームでもファジングするのがよい方法です。

**Docker について。** Docker は、ユーザー空間を隔離するよい方法です。しかし、カーネル空間は隔離しません。AFL++ のようなファザーは、たとえばコアダンプをディスクに保存しないように、システムとカーネルを特定の方法で設定します。このため、Docker ホストをファジング以外にも使っている場合や、複数の Docker コンテナで複数のファジングキャンペーンを並行して実行する場合は、問題が起こりえます。AFL++ が変更したカーネルの実行時設定は、ほかのコンテナを含むシステム全体に影響するからです。

Docker を使うかどうかという問題は、このセクションの最初に挙げた**環境の選択**にも関わります。アプリケーションが普段 Docker で動いているなら、Docker コンテナでファジングするとよいでしょう。

可能であれば、Linux の VM でのファジングをお勧めします。コンテナより隔離性が高いためです。性能面では、ホストとゲストのアーキテクチャが同じネイティブ仮想化を使う場合、[特権付き](https://docs.docker.com/engine/reference/commandline/run/#privileged)の Docker コンテナと VM の差はごくわずかです。ただし、既定の設定の Docker を使うと、性能が最大 50% 低下する点に注意してください。コンテナが[特権付き](https://docs.docker.com/engine/reference/commandline/run/#privileged)でない場合や、[セキュリティ機能](https://mamememo.blogspot.com/2020/05/cpu-intensive-rubypython-code-runs.html)を無効にしている場合は、Docker でのファジングが遅くなることがあります。

**VM でのファジング。** ファジング環境に Linux を使うなら、ファジングのプロジェクトごと、またはキャンペーンごとに別々の VM を作ると、より堅牢な結果が得られます。Trail of Bits のツール [cloudexec](https://github.com/crytic/cloudexec) を試して、複数のクラウド VM にタスクを分散させてもよいでしょう。

Apple のデバイスで Docker Desktop を使っている場合は、実際には macOS から隔離された [VM が内部で起動](https://www.docker.com/blog/the-magic-behind-the-scenes-of-docker-desktop/)している点にも注意してください。
